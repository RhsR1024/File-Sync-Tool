# 远程替换增量更新产品包

## Goal

在 File Sync Tool 中新增一个面向 Linux 安装包的“远程产品包替换”工具：用户填写 SSH 连接信息后，像 XFTP 一样浏览远程 Linux 目录，选择服务器上的 `tar.gz` 安装包，再选择本地要替换的库文件，由工具通过 SSH/SFTP 在服务器本机完成包内文件替换、`md5` 清单更新和新安装包生成。

核心价值是避免 5-6.x GB 解包体积的 `tar.zst` 被拉回 Windows 本地处理，也避免替换后再上传整包到 Linux。Windows 端只承担 UI、连接控制、本地替换文件上传和日志展示；重写压缩包的 CPU/磁盘开销留在目标 Linux 服务器。

## Background And Confirmed Facts

- 典型包结构是外层 `*.tar.gz`，内部包含 `*.tar`，再包含组件目录和 `*.tar.zst`，`tar.zst` 解开后又是 tar 内容。
- 目标 `VMS_U500_H16-B2101.11.0.260612_x86.tar.zst` 解开后可达 5-6.x GB，因此不适合在 Windows 本地完整展开或纯内存处理。
- 目标包一定部署在 Linux 上使用，目标服务器也一定安装 `zstd`，因为安装流程本身需要解压 `.tar.zst`。本功能不需要处理缺少 `zstd` 的兜底场景。
- 压缩包不能真正原地修改其中几 KB。只要内部文件变化，受影响的 tar/zst/gzip 层必须重新写出新文件。
- 现有项目是 Vue + Tauri/Rust 工具，已有 `ssh2`、SFTP 上传、远程命令执行、部署服务器配置和任务日志/进度基础能力。
- 现有 `DeployServer` 配置模型只有密码登录字段；本功能需要支持 SSH 密码认证和私钥认证。
- 现有侧边栏和工具页采用工具卡片 + 独立页面模式，本功能应作为新的工具页进入 `/tools` 区域。

## Requirements

- R1 新增“远程产品包替换”工具入口，放入工具中心和侧边栏工具分组。
- R2 页面支持填写或选择 SSH 连接信息：服务器 IP、端口、用户名、认证方式、密码或私钥信息，并提供连接测试。
- R3 连接成功后，页面提供类似 XFTP 的远程目录浏览器：
  - 支持显示当前路径、上级目录、文件夹和文件列表。
  - 支持双击/回车进入目录。
  - 支持刷新当前目录。
  - 支持选择远程 `*.tar.gz` 安装包。
  - 文件列表应展示名称、类型、大小、修改时间等必要信息。
- R4 页面支持选择本地替换文件。Windows 端只上传该文件到服务器临时目录，不下载远程整包。
- R5 页面支持三段式选择包内目标文件路径：
  - 首先按本地替换文件名扫描远程安装包内的候选目标文件路径，展示候选列表供用户选择。
  - 若扫描不到或文件名不一致，支持浏览包内目录结构，用户手动选择完整包内目录，工具用该目录和本地替换文件名组成目标路径，并允许用户在确认前编辑文件名。
  - 若包内目录浏览仍不能定位目标，提供手动输入完整包内目标文件路径作为兜底。
- R6 替换执行在 Linux 服务器本机完成：
  - 上传本地替换文件到临时工作目录。
  - 读取远程安装包结构。
  - 找到目标内部文件并替换。
  - 计算替换文件的新 MD5。
  - 只更新用户最终选择的包内目标文件路径对应的 `md5` 记录，不按同名文件批量更新，避免误伤其他组件。
  - 若上层 `md5` 清单记录了下层 `md5` 文件本身，则级联更新该下层 `md5` 文件对应的记录。
  - 生成新的安装包文件，默认不破坏原包。
- R7 输出策略提供选项，默认不覆盖原包：
  - 默认模式：生成 `原文件名.patched.tar.gz` 或用户指定的新包路径。
  - 可选覆盖模式：先把原包备份为带时间戳的 `.bak` 文件，再用新包替换原文件名。
  - 覆盖模式必须显式勾选并二次确认，确认界面展示原包路径、新包路径、备份路径和风险提示。
  - 覆盖失败时应保留备份并在日志中给出恢复提示。
- R8 工具应提供执行日志和阶段状态，至少包含连接、上传替换文件、分析包结构、重写内层 `tar.zst`、更新 md5、生成新包、可选备份覆盖、清理临时目录。
- R9 默认假设服务器已有 `tar`、`gzip`、`zstd`、`md5sum` 等基础命令，不实现缺失兜底。
- R10 失败时原安装包必须保持可用；临时目录应尽量清理，无法清理时在日志中给出路径。
- R11 UI 必须适合运维重复操作：信息密度高、步骤清楚、错误靠近问题点、按钮禁用状态明确、支持键盘焦点。
- R12 远程临时工作目录默认创建在原包所在目录旁边，例如 `<package-dir>/.file-sync-tool-patch-<timestamp>/`；首版不把临时目录选择做成主流程问题，后续可按使用反馈增加高级自定义。

## Likely Out Of Scope For MVP

- 不做 Windows 本地完整改包。
- 不做纯内存处理 5-6.x GB 解包体积。
- 不做 zstd 缺失自动安装或自带 Linux helper。
- 不做通用任意压缩格式编辑器，先聚焦已知 `tar.gz -> tar -> tar.zst -> tar` 产品包结构。
- 不直接自动安装产品包；本功能只生成替换后的安装包。

## Acceptance Criteria

- [ ] 工具页可以通过 SSH 连接 Linux 服务器并列出远程目录结构。
- [ ] 用户可以在远程浏览器中选择服务器上的 `*.tar.gz` 安装包。
- [ ] 用户可以选择本地替换文件，工具仅上传该替换文件到服务器临时目录。
- [ ] 用户可以通过“自动候选 -> 包内目录选择 -> 完整路径输入兜底”的顺序确定包内目标路径。
- [ ] 工具在服务器本机生成替换后的新安装包，不下载远程整包到 Windows。
- [ ] 输出策略默认生成新包且不覆盖原包；勾选覆盖模式时会先备份原包并要求二次确认。
- [ ] 替换后的包内目标文件 MD5 与本地替换文件一致。
- [ ] 只更新用户选择的目标路径对应 `md5` 记录；同名但未选中的文件不被批量修改。
- [ ] 需要级联时，上层 `md5` 中引用下层 `md5` 文件的记录也被更新。
- [ ] 失败时原包不被破坏，页面显示可定位的失败阶段和日志。
- [ ] 远程临时工作目录默认位于原包所在目录旁边，日志中展示该目录路径。
- [ ] 远程目录浏览、文件选择、执行按钮均有 loading/disabled/focus 状态。
