# 一体机主备从接入组一键开启SSH与白名单

## Goal

把"一体机 SSH 开启"页面中现有的"经由跳板机的目标"区块**替换**为"主备（从）接入组"区块：一组内输入主机 / 备机（可选）/ 从机（0~10 台）IP，一键完成三类机器的 SSH 开启与 iptables 白名单添加。

角色语义（与现网一体机部署对应）：

| 角色 | 数量 | 开启方式 | 白名单方式 |
|------|------|----------|-----------|
| 主机 | 1（必填） | HTTP 管理接口开启 SSH | SSH 登录主机后本机执行 iptables |
| 备机 | 0~1（可选） | 不经接口（无可达管理接口） | 经主机免密链式 SSH 到备机执行 iptables |
| 从机 | 0~10 | 与主机相同：HTTP 接口直连开启 | 直连 SSH 执行 iptables |

## 需求确认记录（2026-07-09 与用户收敛）

1. **替换**现有跳板机区块，不并存两套界面（备机留空 + 无从机 ≈ 旧跳板对的超集，旧能力不丢失）。
2. 从机可能多台，**上限 10 台**。
3. 存在"只有主+从、无备机"的场景：此时主机与从机都按直连 IP 调接口开启 SSH（主机不再走跳板路径）。
4. 白名单**来源默认值改为"全部放行"（0.0.0.0/0）**；白名单范围保持默认"全部 TCP 端口"。

## Requirements

- R1 组输入：每组包含主机 IP（必填）、备机 IP（可选）、从机 IP 列表（0~10，标签式输入）；可添加多组、删除组。
- R2 目标拆解（前端组装，后端 `enable_appliance_ssh` 命令与请求结构零改动）：
  - 有备机：产生跳板对 target `{ip: 备机, jumpHost: 主机}`（现有路径：接口开主机 SSH → 主机本机白名单 → 链式 SSH 备机白名单）。
  - 无备机：主机产生直连 target `{ip: 主机}`。
  - 每台从机产生直连 target `{ip: 从机}`。
- R3 校验：各 IP 格式校验（沿用现有红框样式）；从机超过 10 台时禁止继续添加并提示；组内主机为空则该组不参与执行。
- R4 直连目标跨"手动 IP / 服务器勾选 / 各组"去重；跳板对按（主机, 备机）去重。
- R5 主机 SSH 端口输入、主机独立凭据开关：仅当存在含备机的组时展示（沿用现有 jump-host 端口/凭据逻辑，仅改文案为"主机"措辞）。
- R6 白名单来源默认选中"全部放行 (0.0.0.0/0)"；范围默认"全部 TCP"（现状即默认）。
- R7 结果展示：沿用现有结果表，组内目标行增加"组 N · 主机/备机/从机"角色徽章；跳板对行内的"跳板机/目标"分组标签改为"主机/备机"措辞。
- R8 最近使用：组记录序列化为 `主=>备=>从1,从2` 存入现有 kv 键（`applianceSsh.recentJumpHostPairs` 的旧条目 `主=>备` 必须能被新解析器兼容读取），上限沿用 5 条，点击回填整组。
- R9 i18n：全部新增/改动文案在 `messages.ts` 同步提供 en + zh；废弃的 jumpHost 区块文案键删除。
- R10 纯逻辑（组校验、目标拆解、序列化/解析、结果角色映射）抽到独立 lib 模块，配 `node --test` 单测。

## Acceptance Criteria

- [ ] 页面上不再出现"经由跳板机的目标"区块，替换为"主备（从）接入组"区块。
- [ ] 主+备+从1+从2 一组执行后：主机 SSH 经接口开启并本机加白名单；备机经主机链式 SSH 加白名单；两台从机各自经接口开 SSH + 直连加白名单（结果表 4 行，各带角色徽章）。
- [ ] 主+备（无从机）一组的行为与旧版跳板对完全一致（含管理接口不可达时的 SSH 降级路径）。
- [ ] 主+从（无备机）一组：主机与从机全部走直连路径，无链式 SSH。
- [ ] 从机标签输入第 11 个 IP 被拒绝并有提示；无效 IP 红框标注且不阻塞其他合法目标。
- [ ] 打开页面时白名单来源默认为"全部放行"，范围默认为"全部 TCP 端口"。
- [ ] 旧格式最近记录 `a=>b` 能显示为"主 a → 备 b"并可回填；新记录带从机可完整回填。

- [ ] 新 lib 模块 `node --test` 通过；`pnpm check`（vue-tsc）与 `pnpm lint` 通过。
