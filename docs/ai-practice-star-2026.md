## 二、AI应用场景与问题背景

### 业务/流程痛点

研发、测试和现场运维过程中存在大量“小而频繁、重复但又不能出错”的工作：人员需要定时查看共享目录是否产生新版本，手动筛选、复制，再登录多台 Linux 服务器上传并执行部署命令；调试视频业务时缺少真实相机和告警场景；异地沟通时仅能看到对方画面，问题位置需要反复口头描述；此外还要在 SSH、SFTP、TFTP、网络诊断、文件共享、错误码查询、剪贴板和便签等多个工具之间来回切换。

这些工作单次看似不复杂，但高频发生，容易产生以下问题：

- 人员被版本巡检和部署流程占用，吃饭、休息或处理其他任务时无法继续推进。
- 多台服务器、多台设备重复操作，容易漏执行、输错地址或无法追溯失败环节。
- 真实摄像机数量和类型有限，测试实况存储、图片存储和带图告警时准备成本高。
- 屏幕沟通只能“看”，不能直接指出位置或协助操作，会议和远程排障效率低。
- 常用工具分散，安装配置、权限准备、结果整理和窗口切换消耗大量时间。

### 为什么引入AI？

传统做法往往是针对单个问题临时写脚本，功能分散、交互不统一，也难以覆盖异常处理和后续复用。项目借助 AI 快速梳理真实工作场景，将零散需求转化为可视化、可配置、可重复执行的桌面工具，并持续完善批量处理、状态反馈、日志留痕和失败重试。AI在本案例中是加速场景分析和工具落地的手段，最终价值体现在工具是否真正减少等待、重复操作和现场资源依赖。

## 三、AI解决方案设计

### AI工具/模型/技术栈

- AI辅助工具：Codex、Claude 系列编程代理。
- 桌面端技术：Tauri 2、Vue 3、TypeScript、Rust、Tokio。
- 系统与协议能力：Windows 原生能力、UNC网络共享、SSH/SFTP、HTTP、RTSP/RTP、TFTP、Web屏幕与文件服务。
- 使用形态：单一 Windows 桌面工具箱，本地运行；任务和服务器配置可保存复用，常用能力可一键触发。

### 核心实现逻辑（150字以内）

借助AI梳理研发、测试和运维中的重复工作，将共享目录巡检、版本拉取、Linux部署、设备模拟、屏幕协作和常用运维操作封装为可配置工具；由人员设定规则，工具自动执行并记录结果，正常流程无需值守，异常时再由人员介入。

### 集成方式

工具以独立 Windows 桌面应用交付，不要求改造现有研发系统。用户安装后即可按需配置共享目录、Linux服务器、设备地址和工具参数；同步任务可自动调度，屏幕共享和文件共享可由浏览器直接访问，其余能力均从统一的“其他工具”入口打开。

### 统一在线升级与分发

工具箱内置在线升级能力，由内部升级服务器统一发布版本、发布日期、更新说明和安装文件。客户端可在应用内自动或手动检查新版本，查看当前版本、最新版本和历史更新内容，并直接下载升级文件；下载过程展示进度和速度，落地前进行SHA-256完整性校验，校验通过后再执行版本替换和重新启动。

这一能力解决了工具使用人员增多后“到处发安装包、版本不一致、无法确认是否下载完整”的问题。维护人员只需向统一发布目录投放一次版本，所有使用者即可从同一来源获取更新；新增功能、问题修复和配置兼容能力能够更快覆盖到团队，避免长期使用旧版本造成重复问题。

### 产品功能、解决痛点与应用价值

#### 1. 同步控制台——从“人工等版本”变为“无人值守拉取并部署”

- **解决的痛点**：新版本生成时间不固定，人员需要反复查看共享目录；发现版本后还要手工复制、等待文件写完、连接 Linux 服务器上传并执行命令。若版本在午休、晚间或人员处理其他工作时产生，部署只能等待人员返回。
- **主要功能**：可配置扫描间隔和生效时段，按版本号、日期、扩展名和文件名关键词筛选目标；发现新版本后先等待文件稳定，再增量复制到本地。复制完成后可自动向多台 Linux 服务器进行 SSH/SFTP 交付，并按任务执行远程命令、本地脚本或组合流程。
- **功能亮点**：实现“发现版本—完整性判断—增量拉取—Linux上传—命令执行—结果记录”全流程自动化。人员离开吃饭或休息期间，工具仍可完成版本拉取和部署，回来后直接查看结果；异常任务支持暂停、继续、取消、重试和补部署。
- **补充能力**：提供任务组状态、实时速度、运行日志和历史记录；支持单路径及多路径手动复制，一次粘贴多条路径、预览目标冲突并批量提交，适合临时取包和补文件场景。

#### 2. UMS初始密码修改——批量完成新设备初始化

- **解决的痛点**：新设备或新环境交付时，需要分别处理框架、UMS和CDM的默认密码；设备数量多时逐台操作耗时，而且不同服务使用的接口和认证方式不同，容易遗漏。
- **主要功能**：支持从已配置服务器中选择设备，也可批量粘贴多个IP；可按需勾选框架、UMS和CDM密码修改流程，一次执行多台设备，并显示成功、失败和具体原因。
- **功能亮点**：把多个服务、多个地址的初始化动作收敛为一次批量任务，保留最近使用IP和完整执行日志，既减少重复输入，也便于定位某台设备失败在哪一步。

#### 3. 一体机访问控制——批量开启SSH并配置访问白名单

- **解决的痛点**：现场一体机可能默认未开启SSH，或被防火墙规则限制；逐台查询状态、调用接口、登录后台并调整iptables规则繁琐，高可用主备机和从机较多时尤其容易漏配。
- **主要功能**：自动查询当前SSH状态，仅对未开启设备执行开启操作；支持主线、组件化等管理接口，支持批量IP和主备从设备组；可选择仅放行SSH端口或放行来源IP的全部TCP端口。
- **功能亮点**：将“状态确认—SSH开启—白名单维护”合并为一条流程，可复用最近IP和设备组，减少现场逐台执行命令的工作量，并避免在已经开启的设备上重复操作。

#### 4. Portal自动登录——开机后自动恢复办公网络

- **解决的痛点**：办公网络需要Portal认证时，电脑重启、网络波动或认证失效后，人员需要打开网页重新登录；无人值守电脑可能因此长时间离线，影响同步、共享和远程任务。
- **主要功能**：保存Portal地址、账号和登录配置，支持检测当前认证状态、立即登录、开机自动登录，并持续展示执行状态和运行日志。
- **功能亮点**：把易忘记的网页认证变为后台自动动作，使依赖网络的同步和运维任务在开机后更快恢复；失败时能够直接查看原因，而不是等到其他任务报错后再倒查网络。

#### 5. 远程产品包替换——无需完整重做大包即可替换内部文件

- **解决的痛点**：调试或紧急修复时，通常只修改产品包内一个文件，却需要人工解开多层tar包、定位内部路径、替换文件、更新MD5、重新打包，再把完整大包上传到服务器。流程长、传输慢且容易破坏包结构。
- **主要功能**：通过SSH浏览远程目录并选择产品包，扫描包内候选路径和嵌套层级；选择本地替换文件后自动重写内部tar包、更新MD5清单、检查空间、上传并执行远程处理，同时显示进度、日志和结果。
- **功能亮点**：把高风险的手工拆包重打包过程变成可预览、可确认的工作台流程。只需选择“哪个包、哪个文件、替换成什么”，即可减少命令输入、完整包重复传输和MD5遗漏。

#### 6. 代码修改统计——自动形成版本代码变更报告

- **解决的痛点**：版本评审、工作量说明或交付审计时，需要统计新增、删除、修改的代码和注释；人工逐目录对比慢，口径也容易不一致。
- **主要功能**：支持“新旧目录增量对比”和“全新项目统计”两种模式，可选择统计目录和文件范围，汇总代码量、注释量及变更明细，并导出CSV或HTML报告。
- **功能亮点**：将临时人工统计转为统一口径的可重复分析，报告既可查看总体结果，也可追溯到具体文件，便于版本汇报、评审和留档。

#### 7. 网络工具——一个页面完成常见网络排障

- **解决的痛点**：现场排障经常需要在Ping工具、端口扫描器、命令行、子网计算器和远程唤醒工具之间切换，信息分散且操作方式不统一。
- **主要功能**：集成Ping扫描、TCP连接统计、TCP端口测试、Wake-on-LAN远程唤醒和子网计算五类能力。
- **功能亮点**：从“主机是否在线、端口是否可达、当前连接是否异常、网段如何划分、关机设备如何唤醒”形成连续排查路径，减少安装多个小工具和反复复制IP地址。

#### 8. 显示器控制——统一调节多显示器亮度与对比度

- **解决的痛点**：实验室、会议室或多屏办公场景中，不同显示器亮度和对比度不一致，需要逐台按物理按钮调整，操作慢且难以快速统一。
- **主要功能**：自动枚举已连接显示器，识别显示器是否提供硬件控制能力，并可分别调整每台显示器的亮度和对比度。
- **功能亮点**：在一个页面集中管理多台显示器，减少寻找物理按键和逐级操作OSD菜单的时间；只对硬件实际支持的参数开放控制，避免无效操作。

#### 9. 屏幕共享——让观看、批注和简单远控形成互动闭环

- **解决的痛点**：传统屏幕共享只能看到画面。代码评审、界面确认或远程排障时，观看者只能反复描述“左上角那个按钮”“这一行日志”，共享者还要自行寻找位置；复杂问题往往需要共享者按他人口述完成操作，沟通轮次多。
- **主要功能**：共享者一键开启局域网屏幕共享，可选择显示器、采集方式、帧率和访问密码；观看者使用浏览器打开链接或扫描二维码即可观看，无需安装客户端，并支持多人同时接入、观看人数和连接IP展示、断线恢复。
- **远程批注亮点**：观看者可使用激光点、箭头和矩形直接标出关注区域；批注可同步到共享者屏幕的透明桌面叠加层，所有参与者看到同一位置。共享者可撤销最新批注、清空全部批注或随时关闭桌面叠加，适合会议讲解、设计评审和远程指导。
- **简单远控亮点**：观看者可申请远程控制，经共享者明确允许后执行鼠标移动、左右键、双击、拖拽和滚轮操作；同一时间只允许一个控制者，共享者可立即收回权限。遇到共享停止、断线、锁屏或采集异常时自动终止控制，兼顾效率与安全。

#### 10. 虚拟设备模拟——没有真实相机也能完成实况、存储和告警调试

- **解决的痛点**：研发和测试视频平台时，不一定具备足够的真实相机；不同设备类型、多个通道和大量并发设备难以准备。测试实况存储、录像、图片存储时需要稳定视频源；验证带图告警则常常要安排人员到镜头前反复走动、露脸或驾驶车辆触发，耗时且难以复现。
- **主要功能**：面向UMS批量创建普通IPC、智能相机、结构化相机、人脸门禁相机、普通NVR和车辆识别NVR等虚拟设备，提供稳定的IP、MAC、序列号和设备身份，支持平台发现、自动添加、在线保持及多设备、多通道运行。
- **实况素材亮点**：提供RTSP实况流，支持主码流、辅码流和第三码流，可切换不同实况素材主题并叠加时间水印；平台能够像使用真实相机一样拉流并验证实况展示、录像和存储流程。素材可从升级服务器增量同步，客户端无需额外安装FFmpeg。
- **带图告警亮点**：结构化相机可模拟机动车、非机动车、行人检测和人脸检测四类带图告警，支持固定、顺序或随机发送，并记录成功、失败、告警开始和恢复结果。测试人员无需准备四类真实相机，也无需反复到镜头前制造事件，即可稳定复现图片接收、检索、存储和展示场景。
- **应用价值**：降低对实验室设备、布线和现场人员的依赖，尤其适合开发初期接口联调、问题复现、批量设备接入、实况/录像存储验证和告警图片链路测试。

#### 11. 文件共享——浏览器打开即用的局域网文件中转站

- **解决的痛点**：临时向同事、测试手机或隔离网络中的电脑传文件时，配置SMB/FTP、创建账号或安装客户端成本高；使用聊天工具传大文件又可能受大小、速度或网络限制。
- **主要功能**：选择一个或多个本地目录并设置别名、端口和访问账号，即可启动局域网文件服务；其他电脑和手机通过浏览器浏览、搜索、上传和下载文件，支持目录打包下载、批量操作、列表/网格视图、深色模式和移动端页面。
- **功能亮点**：共享端一次启动，访问端零安装；可按用户限制不同共享根目录的访问范围，兼顾便利与权限控制。适合版本包、日志、截图和测试素材的临时分发与回收。

#### 12. TFTP文件传输——为串口管理设备快速提供固件和配置

- **解决的痛点**：部分网络设备只能在串口或设备命令行中通过TFTP获取固件、补丁和配置文件。每次临时寻找TFTP软件、配置目录、确认本机地址和手写设备命令，容易出错。
- **主要功能**：选择共享目录或本地文件后启动TFTP服务，自动生成设备侧下载/上传命令，展示共享文件、服务状态、传输数量和实时日志；可按需允许设备上传及控制同名文件覆盖。
- **功能亮点**：把“准备服务—确认文件—生成命令—观察结果”放在同一页面，减少现场搭建时间，适合设备升级、配置导入导出和问题日志回传。

#### 13. 硬盘缓存清理——集中发现并清理设备残留缓存

- **解决的痛点**：一体机磁盘或Redis中可能残留Storage缓存，造成空间占用、槽位状态异常或业务恢复失败。人工逐台SSH登录、查询磁盘和Redis键，再手工删除，效率低且存在误删风险。
- **主要功能**：支持查看Linux设备、Windows本地磁盘和IPSAN相关区域，按主机、槽位和缓存项展示状态；可统一刷新、逐条清理或批量清理残留缓存。
- **功能亮点**：先看清资源和缓存对应关系，再执行有范围的清理，减少盲目执行命令；多台设备可集中处理，适合存储调试、环境恢复和现场空间治理。

#### 14. 剪贴板管理——把临时复制内容变成可搜索的工作资料

- **解决的痛点**：研发人员频繁复制命令、IP、日志、图片和文件路径，后续想再次使用时往往已经被新内容覆盖；重要片段散落在聊天窗口和临时文本中，重复查找、复制和整理耗时。
- **主要功能**：记录文本、图片和文件类剪贴板历史，通过全局快捷键快速唤出；支持搜索、类型筛选、来源识别、自定义分组、收藏、置顶、批量选择和清理。
- **功能亮点**：可直接再次复制或粘贴，支持纯文本粘贴、文件粘贴、路径粘贴、合并粘贴、在资源管理器中定位文件和图片另存为；图片可框选区域后以标准剪贴板格式复制。数据支持导入导出、存储目录调整和应用黑白名单过滤，兼顾效率与隐私。

#### 15. 错误码查询——从翻表和问人变为直接检索

- **解决的痛点**：定位内部错误码时，开发和测试人员常在多个CSV、代码仓库、文档或聊天记录中查找；错误码库更新后，本地旧文件还可能给出过期结论。
- **主要功能**：同步内部GitLab错误码字典并建立本地缓存，支持单个错误码、范围和关键字检索；结果展示中英文消息、解决方案、所属模块和备注，并支持分页浏览。
- **功能亮点**：工具内置同步能力，不要求电脑另行安装Git；同步后可快速本地查询。既减少“这个错误码是什么意思”的重复沟通，也让排障建议与当前字典保持一致。

#### 16. Notepad++扩展中心——统一安装插件并可视化配置日志高亮

- **解决的痛点**：研发环境中的Notepad++版本、安装位置和CPU架构不一致，手工寻找插件、复制DLL和修改配置容易装错；日志关键字高亮规则直接编辑配置文件也不直观。
- **主要功能**：自动识别标准版和便携版Notepad++，从内网插件目录查看、搜索和安装已审核插件；支持架构检查、SHA-256校验和安全解压。对于EnhanceAnyLexer，可在图形界面中编辑关键字、颜色和匹配规则并实时预览。
- **功能亮点**：把“找安装目录—确认架构—下载插件—复制文件—编辑高亮规则”变成可视化流程，便于团队统一日志查看能力，也降低新人配置开发环境的门槛。

#### 17. PaperTodo便签——让待办、笔记和常用脚本停留在桌面工作现场

- **解决的痛点**：临时待办、排障步骤、命令片段和会议记录分散在聊天、记事本和任务系统中；频繁切换窗口容易打断当前工作，也容易忘记短期事项。
- **主要功能**：支持创建待办纸和笔记纸，以独立桌面纸片或屏幕边缘胶囊显示；待办支持进度、筛选、拖动排序、撤销和关联笔记，笔记支持Markdown、图片、目录大纲、编辑/预览分栏，并可用系统编辑器打开。
- **功能亮点**：纸片可置顶、快速显隐并通过全局快捷键打开；可信笔记中的PowerShell脚本可在确认后直接运行，适合保存高频诊断命令。外观、字号和纸片行为可统一配置，数据支持导入导出和未使用图片清理。

## 五、经验总结与影响面

### 关键成功因素

- **从真实小痛点出发**：功能不是为了展示技术，而是直接对应版本等待、远程部署、相机不足、沟通低效和工具分散等高频问题。
- **配置一次、重复使用**：扫描规则、服务器、命令组、设备组和工具参数均可保存，后续任务尽量做到一键执行或无人值守。
- **形成完整闭环**：不仅执行操作，还提供预览、进度、日志、历史、失败原因和重试入口，减少自动化失败后的排查成本。
- **AI是手段，实用性是结果**：利用AI加快需求梳理、交互完善和功能迭代，但案例评价最终落在是否减少人工、现场设备和沟通成本。

### 挑战与应对

- **现场环境和设备版本差异大** → 提供主线/组件化接口选择、多个采集后端、硬件/软件回退和可配置端口，不把单一环境假设写死。
- **自动操作存在误执行风险** → 在批量复制、产品包替换、缓存清理、远控申请等高风险环节提供预览、明确确认、权限控制和随时终止能力。
- **网络或外部设备可能暂时不可用** → 保留任务状态、日志、失败原因和重试入口，使人员只处理异常，而不是重新执行全流程。
- **模拟器需要兼顾真实性与易用性** → 使用稳定设备身份、真实拉流协议、可切换素材和带图告警，同时明确当前面向UMS平台及其能力边界。

### 影响面说明

File Sync Tool 已形成“1个同步控制台 + 16个实用工具 + 统一在线升级”的研发测试运维工具箱，覆盖版本获取与部署、设备初始化、远程访问、产品包修复、视频设备模拟、屏幕与文件协作、网络与存储排障、错误码查询、个人效率管理及工具自身的统一分发等场景。

其中，同步控制台适用于任何存在“共享目录出包—规则筛选—本地落盘—Linux交付—命令执行”流程的产品线；虚拟设备模拟可用于视频平台的接入、实况、录像、图片和告警测试；屏幕共享、文件共享、网络工具、剪贴板和便签等能力则具有更广泛的团队通用价值。后续可通过标准任务模板、命令组模板、设备组模板和操作手册推广到其他研发、测试及现场支持团队。
