# 文件共享界面高密度专业版优化设计

- 日期：2026-04-06
- 状态：设计已确认，待用户 review 文档后进入实现计划
- 适用范围：桌面端文件共享配置页 + share-web 访问页
- 设计方向：`A / 高密度专业版`

## 1. 背景

当前文件共享相关界面已经具备主要能力，但存在三类明显问题：

1. 桌面端配置页里“共享根目录”的命名不准确，实际用户心智更接近“多个可管理的共享目录列表”。
2. 每个共享目录项当前采用大卡片 + 独立启用行的布局，信息密度偏低，纵向空间浪费明显。
3. 配置页与 share-web 访问页视觉语言分裂：前者偏传统白底表单后台，后者偏深色文件浏览器，缺少同一子系统应有的一致性。

同时，当前活跃任务 [`file-share-ui-polish`](../../../.trellis/tasks/04-06-file-share-ui-polish/prd.md) 中已有以下具体 UI 诉求：

1. share-web 面包屑需要更清晰地表达层级。
2. 图片列表缩略图需要在正确的开关条件下显示。
3. 文件共享设置页里的密码输入布局、路径操作按钮等细节需要修正。

本设计将把这些既有 polish 项与本轮新增的整体视觉优化统一到同一份方案中，避免实现时拆成两套方向。

## 2. 设计目标

### 2.1 体验目标

1. 把“共享根目录”统一改名为“共享目录列表”。
2. 把每个共享目录项从“松散卡片”改成“高密度目录行”。
3. 把“启用”控制并入目录项右侧操作区，不再单独占一整行。
4. 把配置页组织成“左侧配置主区 + 右侧运行控制副区”的工作台结构。
5. 让 share-web 访问页延续高效表格浏览，但在颜色、间距、按钮和状态表达上与配置页统一。
6. 保留当前功能能力，不通过视觉改造引入权限、导航或运行时语义回归。

### 2.2 实施目标

1. 优先通过前端布局重组、组件微调、文案收敛和样式统一完成本轮优化。
2. 保持与当前 dirty worktree 中已有的文件树统一改造兼容，不覆盖或回退正在进行中的结构变更。
3. 将已有 UI polish 任务中的细项一并纳入，避免后续重复返工。

## 3. 范围与非目标

### 3.1 本轮范围

1. 桌面端文件共享配置页的信息架构、布局、文案、按钮层级和样式优化。
2. share-web 工具栏、搜索区、文件表格、行操作、面包屑与缩略图呈现优化。
3. 密码输入布局、路径编辑按钮文案和 nowrap 等现有细节问题修复。
4. 统一两端的状态 badge、卡片风格、按钮体系和色彩层级。

### 3.2 明确不做

1. 不在本轮改变后端权限模型与文件树语义。
2. 不在本轮新增新的共享功能入口或新的权限类型。
3. 不把访问页改成大卡片流式布局，仍保持文件管理器式表格。
4. 不对与本轮目标无关的页面做全站主题重构。

## 4. 方案选择结论

本轮采用 `A / 高密度专业版`，原因如下：

1. 最贴合“共享目录列表”“启用并入操作区”“整体更专业紧凑”的目标。
2. 比平衡卡片版更节省空间，适合目录列表、账号列表、状态卡这类工具型界面。
3. 比深色控制台版更容易和主应用现有浅色后台风格衔接，风险更低。
4. 能让配置页与访问页在不强制同底色的前提下，形成统一的子系统视觉语言。

## 5. 总体信息架构

### 5.1 配置页

配置页采用桌面端两栏布局：

1. 左侧主区承担编辑与配置：
   - 共享目录列表
   - 基础设置
   - 访客与账号
   - 其他访问行为开关
2. 右侧副区承担运行与反馈：
   - 当前运行状态
   - 保存 / 启停 / 重启
   - 访问地址与二维码
   - 统计信息
   - 连接 IP 与日志

这使“配置内容”和“运行控制”视觉上分离，用户在使用时更容易形成稳定心智模型。

### 5.2 访问页

访问页继续采用单主面板结构，但顶部和内容区重组为更明确的三层：

1. 顶部工具层：面包屑、会话状态、刷新与写操作。
2. 搜索层：搜索范围切换、输入框、搜索与清空操作。
3. 内容层：文件表格、空态、错误态、成功反馈。

## 6. 桌面端配置页设计

## 6.1 标题与状态区

页头保留文件共享标题、当前主访问地址和运行状态 badge，但做以下优化：

1. 状态 badge 视觉上更轻，避免比主标题更抢眼。
2. 地址说明作为次级信息，不与配置表单抢层级。
3. 运行中的强调色与访问页的主强调色统一为 teal/cyan 系。

## 6.2 “共享目录列表”替代“共享根目录”

原“共享根目录”卡片更名为“共享目录列表”，对应文案和空态说明同步更新：

1. 标题强调这是“列表”而不是单一根目录。
2. 空态强调“添加共享目录后即可对外共享”。
3. “添加目录”按钮保留在列表头部右侧，作为该模块唯一主入口。

## 6.3 共享目录项改为高密度目录行

每个共享目录项从大卡片调整为紧凑目录行，结构如下：

1. 第一行左侧：
   - 目录别名输入框或别名主信息
2. 第一行右侧：
   - 启用开关
   - 更换路径按钮
   - 删除按钮
3. 第二行整行：
   - 当前真实路径，作为次级信息显示

对应规则：

1. “启用”不再单独占据整行。
2. “更换路径”按钮文案明确表达这是修改当前配置路径，不允许换行。
3. 删除按钮维持危险态，但尺寸与其他按钮统一。
4. 路径文本允许截断，但需保留悬停可读性或完整文本显示能力。

## 6.4 目录项状态表达

目录项的状态表达遵循“对象内聚”原则：

1. 启用状态由行内开关直接表达。
2. 如未来需要“路径失效”“目录不可达”等异常状态，显示在路径下方或路径右侧，不再新增独立横条。
3. 默认情况下不额外增加解释性文案，保持列表干净。

## 6.5 其他配置区收敛

基础设置、访客与账号、其他行为开关继续存在，但视觉上做以下统一：

1. 卡片圆角、边框和内边距缩小，向“专业后台密度”收敛。
2. 表单标签与输入垂直节奏统一。
3. 密码输入框左侧图标与文本留白重新校正，避免视觉重叠。
4. 所有容易折行的路径类按钮和操作按钮均使用 nowrap 约束。

## 6.6 右侧运行控制面板

右侧副区作为运行控制面板，承载：

1. 保存配置
2. 保存并重启 / 启动共享
3. 停止共享
4. 启用目录数、启用账户数等摘要信息
5. 访问地址、复制、二维码、浏览器打开
6. 连接数、运行时长、IP 列表和运行日志

这里不再追求“大按钮堆叠的视觉存在感”，而是强调清晰的控制顺序和一致的按钮层级。

## 7. share-web 访问页设计

## 7.1 顶部工具栏

工具栏保留原有能力，但重新梳理优先级：

1. 左侧优先展示面包屑路径，而不是仅靠 chip 堆叠。
2. 右侧依次放置刷新、写操作、会话状态与账号切换动作。
3. 当用户只有浏览权限时，仅保留必要动作，其他入口自然消失。

## 7.2 面包屑层级可读性

面包屑应更接近真实路径，而不是一串彼此割裂的胶囊：

1. 当前节点需要明显高亮。
2. 分隔符和非当前层级弱化。
3. 在窄屏下允许横向滚动或折叠，但不能破坏层级含义。

## 7.3 搜索区统一

搜索区与配置页视觉语言对齐：

1. 搜索范围切换保留，但做成更紧凑的 segmented control。
2. 输入框、搜索按钮、清空按钮统一圆角、边框和高度。
3. 搜索态、加载态和清空态反馈风格与配置页提示条统一。

## 7.4 文件表格保持高效浏览

访问页内容区继续保留表格式浏览，不改成大卡片。表格优化方向为：

1. 行高略紧凑但保持可点击性。
2. hover 高亮更明确。
3. 表头和内容的间距更加稳定。
4. 文件名、大小、修改时间、操作区仍保持一眼可扫读。

## 7.5 缩略图规则

图片前导缩略图作为高优先级 polish 项纳入本设计，规则为：

1. 仅当 `thumbnail_enabled = true` 时显示列表缩略图。
2. `image_preview_enabled` 是缩略图和预览能力的总开关；若关闭，则缩略图也必须关闭。
3. 缩略图尺寸保持小而稳定，作为前导视觉锚点，不应挤压文件名主信息。
4. 缩略图加载失败时回退到常规文件图标，不产生布局抖动。

## 7.6 行操作按钮收紧

当前访问页里下载、预览等操作按钮颜色较跳、体积偏大。本轮统一调整为：

1. 更小、更规整的按钮尺寸。
2. 保留语义色差，但降低饱和度与视觉噪声。
3. 同类动作跨页保持同一层级含义：
   - 主动作：主要运行操作
   - 次动作：刷新、切换、编辑路径、复制等
   - 危险动作：删除、停止共享

## 8. 视觉系统

## 8.1 色彩

统一采用 `slate + teal + cyan + restrained red` 体系：

1. 配置页主背景保持浅色，适合表单录入。
2. 访问页可保留深色内容面板，但强调色与配置页统一。
3. 成功态使用 teal/green，次强调使用 cyan/blue，危险态使用克制的 red。
4. 避免同时出现过多高饱和大面积按钮色块。

## 8.2 卡片与容器

1. 卡片圆角从偏松的大圆角收紧到更专业的中圆角。
2. 边框与阴影减轻，更多依靠层级和间距组织信息。
3. 左主右辅结构中，主内容区域比右侧运行控制更有视觉重量。

## 8.3 按钮层级

统一为三层：

1. 主按钮：保存、启动、保存并重启。
2. 次按钮：刷新、更换路径、切换账号、复制。
3. 危险按钮：删除、停止共享。

## 8.4 字体与信息密度

本轮不强制引入新的全局字体，而是在现有项目字体体系下优化：

1. 标题层级更明确。
2. 辅助信息字号更小、更克制。
3. 路径和状态说明使用次级文字色。
4. 整体视觉效果向“高密度专业后台”收敛，而不是装饰型设计。

## 9. 响应式策略

### 9.1 配置页

1. 桌面端保持左主右辅。
2. 中等宽度下两栏纵向堆叠，右侧运行控制移到主区下方。
3. 窄屏时目录项和账号项允许内部折行，但操作按钮仍贴近所属对象。

### 9.2 访问页

1. 桌面端继续表格布局。
2. 中小屏下允许表头收起、行内容转为纵向信息块。
3. 必须避免水平溢出；如列过多，优先压缩操作区而非破坏主信息可读性。

## 11. 验收标准

### 11.1 配置页

1. “共享根目录”已替换为“共享目录列表”。
2. 每个共享目录项的启用开关已并入目录操作区。
3. “更换路径”类按钮不再换行，且文案表达清晰。
4. 密码输入框图标与文本不再出现视觉重叠。
5. 桌面端可明显感知“左侧配置、右侧运行控制”的布局层次。

### 11.2 访问页

1. 面包屑以更自然的路径层级方式呈现。
2. 表格在保持浏览效率的前提下完成视觉收敛。
3. 图片文件在允许条件下显示稳定的前导缩略图。
4. 关闭缩略图或关闭图片预览后，缩略图会同步消失。
5. 行操作按钮更加紧凑、规整且不造成视觉跳跃。

### 11.3 一致性与回归

1. 配置页与访问页看起来属于同一套文件共享子系统。
2. 保存、启动、停止、搜索、下载、预览、切换账号等现有能力无回归。
3. 窄屏与移动端不出现明显横向溢出和错位。

## 12. 风险与约束

1. 当前 worktree 已存在文件树统一相关变更，UI 改造必须在其基础上兼容演进，不能回退到旧模型。
2. share-web 缩略图的最终显示依赖后端提供的运行时开关信息，前端不可自行猜测。
3. 目录项高密度化后，仍需确保点击热区、键盘焦点和可读性不被牺牲。
4. 访问页视觉统一时，不能牺牲文件浏览效率去追求纯装饰效果。

## 13. 设计结论

本轮不把文件共享界面理解为“两个相似但无关的页面”，而是把它们统一视为同一子系统的两个工作面：

1. 桌面端配置页负责“配置与运行控制”。
2. share-web 访问页负责“浏览与操作执行”。

`A / 高密度专业版` 的价值在于：

1. 纠正“共享根目录”的错误心智。
2. 消除目录项中浪费空间的独立启用行。
3. 在不改变核心功能语义的前提下，让两页获得一致、专业、紧凑的工具化体验。
