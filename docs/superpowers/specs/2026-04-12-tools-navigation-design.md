# 工具导航改版设计

## 1. 背景

当前工具导航存在两个连在一起的问题：

1. 进入具体工具路径过长。用户从任意页面进入“开启一体机 SSH”这类工具时，通常需要先点击“其他工具”，再进入工具卡片。
2. 左侧侧边栏虽然已经支持子项展开，但整体视觉重量依然偏大，且对工具页的横向空间占用明显，气质更像“后台菜单”，不像轻量、高频切换的桌面工作台。

这次改版不以最小改动为目标，而是优先追求两个结果：

1. 在任意页面都能直接切到具体工具。
2. 用更轻、更现代的结构替换当前左侧侧边栏主导的布局。

## 2. 目标与非目标

### 2.1 目标

1. 采用 `Concept A`：顶部全局导航 + Tools Mega Panel。
2. 保留 `/tools` 作为工具总览页，但不再让它承担唯一入口角色。
3. 让顶部导航在所有页面常驻，用户始终能从当前工具一跳切到别的工具。
4. 弱化原有左侧导航岛的体量，释放主画布横向空间。
5. 视觉延续现有项目的浅色玻璃卡片、柔和渐变、圆角语言，但整体结构升级为更“桌面应用化”的顶部框架。

### 2.2 非目标

1. 本次不重新设计每个工具页内部业务表单。
2. 本次不新增复杂个性化能力（例如收藏、最近使用、拖拽排序）。
3. 本次不改变现有工具路由语义和页面核心功能。

## 3. 决策结论

### 3.1 选型

采用“顶部全局导航 + Tools Mega Panel”替代“左侧侧边栏 + 工具分组展开”的主导航方式。

### 3.2 核心原因

1. 比左侧手风琴更轻。导航从纵向占位转为横向薄条，主内容区更完整。
2. 比悬浮发射器更稳。工具入口永远可见，不依赖用户记忆额外按钮或快捷方式。
3. 比工具条带更统一。控制台、任务、历史、设置、工具都被纳入同一层级，不会在工具页内部再额外生成一层“小导航系统”。

## 4. 信息架构

### 4.1 一级导航

顶部导航保留 5 个一级入口：

1. `Console`
2. `Tasks`
3. `History`
4. `Settings`
5. `Tools`

其中前 4 个继续作为普通路由入口；`Tools` 变为“可点击打开 Mega Panel 的导航项”，默认行为不再直接跳转 `/tools`。

### 4.2 Tools 层级

`Tools` 下挂所有具体工具：

1. 修改框架默认密码
2. 开启一体机 SSH
3. 代码统计
4. 网络工具
5. 屏幕共享
6. 文件共享

### 4.3 `/tools` 的角色

`/tools` 仍然保留，但角色从“唯一入口”调整为“工具总览与浏览页”：

1. 用户通过 Mega Panel 底部的“查看所有工具”入口进入 `/tools`。
2. `/tools` 不再承担“必须先经过这里才能进入具体工具”的职责。
3. `/tools` 主要承担工具浏览、全量查看和低频发现的角色。

## 5. 页面结构设计

### 5.1 应用框架

应用整体从“左侧岛状 Sidebar + 右侧内容区”改为“顶部浮动导航条 + 下方内容区”。

新结构如下：

1. 最外层仍保留现有浅色渐变背景。
2. 顶部增加固定或粘性导航条，宽度与主内容容器对齐。
3. 主内容区在导航条下方滚动，并为固定导航预留顶部间距，避免内容被遮挡。

### 5.2 顶部导航条

顶部导航条应具备这些视觉特征：

1. 玻璃态半透明白底，保留现有设计语言的延续性。
2. 高度偏薄，建议约 `56px - 64px`，避免产生新的“厚头部”。
3. 左侧为品牌区，中部为一级导航，右侧预留轻量状态区或空白，不强塞功能。

一级导航交互规则：

1. 当前路由对应项高亮。
2. `Tools` 在位于任何 `/tools/*` 路由时保持选中态。
3. `Tools` 点击后默认打开 Mega Panel，而不是立即跳 `/tools`。
4. `Tools` 导航项的主动作是打开 Mega Panel；进入 `/tools` 总览页统一通过 Mega Panel 底部链接完成，不在导航项本体上拆分双重点击区域。

### 5.3 Tools Mega Panel

Mega Panel 是本次改版的核心组件，应作为顶部导航下方展开的浮层出现。

面板内容结构：

1. 标题区：说明这是“工具箱”或“快捷进入工具”。
2. 工具卡片区：2 列或 3 列紧凑卡片，展示图标、标题、1 行描述。
3. 底部辅助区：提供“查看所有工具”入口。

交互规则：

1. 点击 `Tools` 打开或关闭面板。
2. 点击工具卡片直接进入对应路由。
3. 点击面板外区域关闭。
4. 按 `Esc` 关闭。
5. 保持键盘可导航，支持 Tab 焦点移动。
6. 返回键与浏览器历史行为保持自然，不通过 `replace` 破坏导航栈。

状态展示：

1. 对运行中的工具可显示轻量状态点，例如屏幕共享、文件共享。
2. 当前所在工具应在面板中有明确高亮。
3. 不在面板中堆叠过多统计信息，避免从“快捷入口”变成“复杂工作台”。

### 5.4 工具页内部体验

用户进入任一工具页后，不再需要依赖左侧子菜单。

工具页内体验目标：

1. 顶部导航始终存在，工具切换路径统一。
2. 工具页自身顶部只负责当前页面的标题、说明和局部操作，不再承担“跳往其他工具”的主要职责。
3. 如果页面已经有自己的二级工具条，保留其业务含义，不与全局导航混淆。

### 5.5 工具总览页

`/tools` 作为总览页继续保留当前卡片式浏览体验，但需要与新的顶部导航配套调整：

1. 页面头部文案改为“浏览全部工具”而不是“这里是唯一入口”。
2. 顶部导航中的 `Tools` 仍为高亮态。
3. 页面可减少“总览页”的说明性负担，把重点放回工具卡片本身。

## 6. 视觉方向

### 6.1 总体气质

本次改版应呈现“专业控制中心”而不是“传统管理后台”：

1. 导航从笨重的纵向模块变成轻薄的横向框架。
2. 继续使用浅色背景、玻璃面板、柔和阴影和大圆角。
3. 通过导航重心上移，让画面更像桌面应用或现代效率工具。

### 6.2 颜色与强调

基于当前项目风格，沿用青绿/蓝色系作为主强调色：

1. 主强调色用于当前导航态、当前工具高亮和运行态状态点。
2. 悬浮层和卡片背景维持高亮白，不使用过重底色。
3. CTA 或跳转强调可以继续允许橙色点缀，但不应进入主导航主色。

### 6.3 动效

动效应轻、短、稳定：

1. 顶部导航 hover 仅做颜色和背景变化，不做大幅缩放。
2. Mega Panel 打开使用轻微向下浮现和透明度过渡。
3. 所有过渡时长控制在 `150ms - 220ms` 左右。
4. 需要考虑 `prefers-reduced-motion`。

## 7. 组件与代码组织建议

### 7.1 共享工具元数据

当前工具列表同时存在于 Sidebar 和 ToolsHubPage。改版后应提取为共享数据源，例如：

1. `src/lib/toolsNavigation.ts`
2. 或 `src/features/tools/navigation.ts`

其中统一维护：

1. 标题 i18n key
2. 描述 i18n key
3. 路由 path
4. 图标
5. 运行态映射 key（如适用）

这样顶部导航、Mega Panel、`/tools` 总览页都可复用同一份工具定义，避免继续三处维护。

### 7.2 顶部导航组件

新增顶层导航组件，建议命名类似：

1. `TopNavigationBar.vue`
2. `ToolsMegaPanel.vue`

`App.vue` 负责提供整体壳层布局与面板挂载位置。

### 7.3 Sidebar 的处理

旧 `Sidebar.vue` 不再作为主布局的一部分使用。

处理建议：

1. 直接从 `App.vue` 中移除。
2. 暂不保留“左侧缩窄版 Dock”，避免形成半新半旧的折中结构。

## 8. 交互与可用性约束

1. 顶部固定导航必须为内容区预留顶部空间，避免遮挡首屏内容。
2. Mega Panel 不依赖 hover 才能使用，点击是主触发方式，hover 只可作为增强。
3. 面板在窄宽度下要安全退化，可改为单列或抽屉式浮层。
4. 当前选中态不能只靠颜色，还需要背景或边框对比。
5. 所有可点击导航项都需有明确 `cursor-pointer`、focus-visible 与键盘焦点样式。

## 9. 风险与取舍

### 9.1 风险

1. 从侧边栏切到顶部导航后，原页面纵向留白与容器宽度可能需要联动微调。
2. 固定头部会影响首屏 spacing，需要逐页检查。
3. 某些工具页如果原本依赖较大的横向容器偏移，布局观感可能会发生变化。

### 9.2 取舍

1. 为了更强的视觉统一性，本次明确放弃“继续美化左侧手风琴”的路线。
2. 为了可发现性与稳定性，本次不选择纯发射器/纯命令面板作为主导航。
3. 为了降低理解成本，本次保留 `/tools` 总览页，但弱化其入口垄断地位。

## 10. 验证标准

设计完成后，应满足以下结果：

1. 从任何页面进入“开启一体机 SSH”只需 1 次主导航操作 + 1 次目标选择，不再强制先到 `/tools`。
2. 左侧不再存在当前这类厚重的主导航岛。
3. 在控制台页、设置页、具体工具页中，顶部导航表现一致。
4. `/tools` 仍可访问，且与 Mega Panel 使用同一套工具定义与视觉语言。
5. 屏幕共享、文件共享等运行态工具在导航中可被快速识别。

## 11. 测试建议

### 11.1 交互测试

1. 点击 `Tools` 可打开/关闭 Mega Panel。
2. 点击面板外可关闭。
3. `Esc` 可关闭。
4. 从面板进入任意工具后，当前项高亮正确。
5. 浏览器前进/后退行为正常。

### 11.2 页面测试

1. 控制台页导航不遮挡内容。
2. 工具总览页与具体工具页的顶部间距一致。
3. 小屏宽度下导航不换行错位。

### 11.3 回归测试

1. 屏幕共享、文件共享运行态指示仍正确。
2. 原有路由路径不变。
3. i18n 文案完整，中文与英文都可用。

## 12. 实施建议

后续实现阶段按以下顺序推进：

1. 提取共享工具元数据。
2. 新建顶部导航与 Mega Panel 组件。
3. 改造 `App.vue` 布局，移除 `Sidebar.vue`。
4. 调整 `/tools` 总览页与新导航视觉衔接。
5. 做路由高亮、运行态和键盘交互收尾。

---

本设计选择 `Concept A` 作为主方向，目标不是“把旧侧边栏挪到顶部”，而是把整个应用的导航体验升级为更轻、更快、更像现代桌面工作台的结构。
