# 同步、部署编排与控制台重构设计

状态：已实现并完成开发环境验收（2026-09-08）。真实一体机与 UNC 编译目录的现场抽样项见对应 Plan 的“实施结果与现场联调清单”。

日期：2026-09-04  
状态：已确认，进入实施  
范围：同步任务配置、扫描与复制、手动/自动部署、安装后操作、主备从搭建、历史清理、任务状态持久化及同步控制台。

## 1. 背景

现有工具已具备单路径扫描复制、SSH/SFTP 部署、远程命令、一体机访问控制、框架/UMS/CDM 初始密码修改和后端任务状态机，但能力仍然彼此独立：

1. 部署只按保存的一组 SSH 参数连接，无法自动探测两套设备默认通道。
2. 安装命令完成后任务即结束，没有跨设备重启的持久化后处理。
3. 主备、主从、主备从没有统一编排和最终验证。
4. 扫描任务只能配置一个源路径，不能把相关组件作为一个业务任务。
5. 任务列表以构建目录 C... 为主要名称，缺少产品、版本、架构和构建时间。
6. 历史记录和本地包没有按天保留策略；全量快照、全量列表和全局日志过滤会放大卡顿。

本设计建立两条后端状态机：

- 同步复合任务状态机：父任务负责汇总，模块子任务隔离复制、部署和失败。
- 部署后处理状态机：连接、上传、安装、重启等待、SSH、拓扑、验证、改密均为可追踪阶段。

## 2. 已确认决策

1. 两套默认 SSH 用户名均为 root。
2. 开启 SSH 接口成功但 23333 仍不可用时继续降级到 22。
3. 安装后 SSH 默认白名单为全部 TCP 端口、来源 0.0.0.0/0 全部放行。
4. 重启恢复每 30 秒检查一次，总时限 10 分钟。
5. 允许多个从机，逐台搭建和验证。
6. 构建时间暂取源构建目录修改时间。
7. 自动清理本地实际包和任务记录。
8. 每个模块至少保留最近一个成功包，即使超过保留天数。
9. 组件化复合任务当天无产出时不回退旧包。
10. 纯主从主机 haType 暂按 1 判断。
11. 切换请求已发送但连接断开后先轮询；10 分钟仍无法确认时标记结果未确认，不自动重复调用。
12. 正式控制台以 docs/design/sync-console-task-list-prototype.html 为交互基线。

## 3. 非目标

1. 不修改远端共享目录中的源构建。
2. 不把 Base64 当作安全加密；密码和 token 不进入日志、通知或任务持久化。
3. 不自动重放结果不明确的拓扑切换接口。
4. 不让前端从日志文本推断业务状态。
5. 不引入通用工作流引擎。

## 4. 部署 SSH 自动探测

### 4.1 连接顺序

手动和自动部署共用同一解析器，执行完整 TCP、SSH 握手和密码认证：

1. root@目标IP:23333，密码 admin_123。
2. 失败后调用一体机 SSH 开启接口。
3. 接口成功后等待状态生效，再试 root@目标IP:23333，密码 admin_123。
4. 接口失败或第二次 23333 仍失败，尝试 root@目标IP:22，密码 123456。
5. 全部失败才结束部署。

解析器返回本次执行的有效 host、port、user、password，供 SFTP、远程目录、安装命令和后处理使用；不覆盖保存配置。

### 4.2 错误结果

失败结果必须聚合：

- 23333 初次尝试的阶段和原因；
- 开启 SSH API 的结果；
- 23333 重试结果；
- 22 降级结果；
- 检查网络、SSH、防火墙、端口、用户名和密码的用户建议。

## 5. 安装后自动操作

### 5.1 配置

部署配置增加：

- 开启一体机 SSH，默认开启；
- 全部 TCP、0.0.0.0/0 白名单并展示高风险说明；
- 搭建主备、主从或主备从；
- 修改初始密码，默认开启；
- 框架、UMS、CDM 分别勾选并设置新密码。

默认新密码：

- 框架：admin_123
- UMS：admin_1234
- CDM：admin_123

UMS 用户名默认 loadmin，允许填写其他已存在用户。框架和 CDM 用户名固定 admin。

### 5.2 执行顺序

连接解析 → 上传 → 安装命令 → 等待首次重启恢复 → 开启 SSH 和白名单 → 拓扑切换与验证 → 修改三类密码 → 完成。

密码修改放在拓扑完成后，避免拓扑过程中途更换框架鉴权密码。

### 5.3 持久化

后处理由 Rust 后台任务执行，不依赖 Vue 页面。每阶段记录：

- 阶段名、状态、开始和结束时间；
- 当前轮询次数和下次轮询时间；
- 每个节点结果；
- 可安全显示的错误摘要；
- 是否可从失败阶段继续。

应用重启后，未完成阶段恢复为 interrupted 或可恢复等待状态。

## 6. 主备从编排

### 6.1 模式与参数

支持无拓扑、单主备、单主从、主备从。

主备参数包括主机 IP、备机 IP、当前框架密码和虚拟 IP。主从参数包括主机 IP 与一个或多个从机 IP。单主从的 primaryIp 使用主机 IP，主备从使用虚拟 IP。主机 hostname 和从机 replicaName 由对应 IP 去点生成，备机 hostname 固定为 HA，与已确认的接口样例保持一致。

### 6.2 切换接口

单主备和主备从先向主机调用：

POST http://主机IP/openAPI/serverMgr/v1/groupType/switch/singleToHA

hAPrimaryServerPasswd 和 hAReplicaServerPasswd 使用 UTF-8 Base64 编码。

单主从或主备完成后，对每个从机顺序调用：

POST http://从机IP/openAPI/serverMgr/v1/deployType/switch/singleToReplica

### 6.3 断连语义

- 请求发送前的 DNS、连接、序列化失败：调用失败。
- 请求已发送后出现 EOF、connection reset、响应不完整：switch_triggered，进入恢复轮询。
- 返回明确业务拒绝：调用失败。
- 正常返回成功：进入恢复轮询。

结果不明确时不得立即重发。

### 6.4 框架鉴权和列表验证

每次重启恢复后重新登录：

POST http://IP:21900/openAPI/userMgr/v1/login

使用框架 admin 当前密码取得 data.token。随后调用：

POST http://主机IP:21900/openAPI/res/v1/query  
请求头 Authorization: token  
请求体 {"resType":2,"parentOrgCode":1}

验证不能只看 total，还要校验配置 IP 和角色：

- 单主备：总数 2，主机 haType=1，备机 haType=2。
- 单主从 N 台：总数 1+N，主机暂按 haType=1，每个从机 haType=4。
- 主备从 N 台：总数 2+N，一个 haType=1、一个 haType=2、N 个 haType=4。
- 所有目标 isDeployed=1、serverStatus=1。
- 主备节点 virtualIP 与配置一致。

返回顺序不参与判断。

### 6.5 HA 状态验证

有主备时额外调用：

POST http://虚拟IP:9820/api/status  
请求体 {"Authorization":"框架 token"}

成功条件：

- ErrCode=0；
- master 和 slave 均存在；
- 两者 HASTATUS=online；
- 两者 HASTARTSTATUS=YES；
- master PDTSTATUS=running；
- backup PDTSTATUS=stop 可接受；
- offlineReason 不单独导致失败。

### 6.6 独立搭建

部署配置提供不上传、不安装版本的独立主备从搭建功能。它和安装后自动搭建共用编排器、状态模型、日志、取消和重试能力，并生成控制台任务记录。

## 7. 复合扫描任务

### 7.1 配置模型

一个 ScanTask 可以包含一个或多个 ScanTaskModule。旧任务自动归一化为单模块，保持行为。

模块字段：

- 稳定 module_id；
- 产品或模块名称；
- remote_path；
- 可选 local_path；
- 独立匹配规则；
- 是否启用；
- 可选服务器与脚本覆盖，空时继承父任务。

批量录入支持每行一个 UNC 路径，解析产品、版本和架构，去重校验后一次保存为一个复合任务。

### 7.2 扫描与执行

1. 发现阶段扫描全部启用模块的今日目录。
2. 计划阶段区分今日有产出、今日无产出、扫描失败。
3. 执行阶段按配置顺序串行处理有产出的模块。
4. 汇总阶段由父任务聚合结果。

组件化复合任务不使用前三天 fallback。今日无产出是正常中性终态。

### 7.3 进度

- 今日产出 5/10：启用模块中发现有效构建的数量。
- 正在处理 3/5：当前处理今天第几个有效模块。
- 复制进度 79%：有效模块按总字节数加权的复制字节进度。

无产出模块不进入字节分母。部署服务器进度与复制进度分开表达。

### 7.4 父子状态

父任务持有批次运行，模块继续建立独立子运行。模块支持待扫描、有产出、无产出、排队、复制、本地脚本、部署、等待重启、后处理、完成、失败、取消和中断。

no_output 不导致 partial_failed。模块失败只影响自身；父任务支持只重试失败模块和从失败阶段继续。

## 8. 任务业务元数据

扫描时解析并持久化 product、version、architecture、build_date、build_time、build_id、configured_task_name、module_id 和 module_name。build_time 暂取源构建目录修改时间。解析失败时保留原路径，不虚构字段。

任务主标题使用产品或复合任务名称，C... 作为辅助构建身份。

## 9. 历史和本地包保留

配置包括自动清理、默认保留 5 天、清理本地包、清理任务记录、每模块保留最近成功包。

应用启动后每日最多自动执行一次，也支持控制台手动预览和执行。

本地清理必须：

1. 只处理明确配置的本地同步根目录。
2. canonicalize 根目录和候选路径。
3. 拒绝根目录自身、根目录外路径和符号链接逃逸。
4. 跳过运行中、待部署、等待重启、后处理和可重试任务引用。
5. 每模块保留最近成功包。
6. 不删除远端源目录。
7. 返回数量、字节数和跳过原因。

任务记录按完成时间清理，与包清理分别统计；max_task_records 必须真正生效。

## 10. 同步控制台

正式实现采用已确认原型：

- 父任务默认折叠，展开显示模块；
- 搜索产品、版本、构建 ID 和路径；
- 状态、类型、异常筛选；
- 显示产品、版本、架构、源目录修改时间、构建 ID；
- 显示扫描、复制、脚本、部署、重启、SSH、拓扑、改密流水线；
- 详情显示路径、模块、服务器、历史、错误和日志；
- 保留暂停、恢复、取消、重新执行、重试部署、清理、打开和复制路径。

状态同时使用文字和图标。详情支持焦点约束、Esc 和焦点归还。

## 11. 性能

1. 后端真正执行记录上限和按天清理。
2. 列表分页或窗口化，不一次渲染全部历史。
3. 高频状态采用增量或节流快照；日志更新不触发列表全量快照。
4. 大型任务集合使用浅响应或不可变摘要。
5. 仅可见活动行订阅秒级计时。
6. 详情日志按任务索引和按需加载。
7. keep-alive 只保留必要页面。

优化结论以现场 profile 为准。

## 12. 兼容与安全

新增字段同步 Rust AppConfig、SyncConfigPatch、默认值、normalize、TypeScript、configDomains 和测试。旧单路径任务归一化为一个模块；旧 task_state 缺字段时以 serde default 加载并升级版本。

密码、Base64 密码和 token 不进入任务持久化。所有提示和确认使用应用内组件与中英文 i18n。

## 13. 验收标准

1. 手动和自动部署使用相同的 23333→开启接口→23333→22 策略。
2. 四个阶段全部失败才报连接失败，并展示聚合建议。
3. 安装后等待每 30 秒执行，10 分钟超时。
4. 主备、主从、主备从按 IP、数量、haType 和 HA 状态验证。
5. 切换接口主动断连不误报普通失败，未确认不自动重放。
6. 可以不部署版本直接创建主备从任务。
7. UMS 支持自定义已有用户名，三套新密码独立且默认正确。
8. 10 条路径可保存为一个任务；只有 5 个产出时显示 5/10、处理 3/5，其余为今日无产出。
9. 新建规则默认组件化，规则标签按产品术语显示。
10. 任务展示产品、版本、架构、构建时间和构建 ID。
11. 可预览并清理 5 天前本地包和任务记录，同时保留各模块最近成功包。
12. 大历史量下有限渲染，日志和计时不再导致无关全量重算。
