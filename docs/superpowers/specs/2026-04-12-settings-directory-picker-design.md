# 设置页目录选择组件设计

- 日期：2026-04-12
- 状态：设计已确认，待用户 review 后进入实现
- 适用范围：`SettingsPage.vue` 中的本地存储、手动部署、任务编辑
- 设计选择：`组件化方案`

## 1. 背景

当前设置页里有 3 处与本地目录相关的输入：

1. 设置 -> 本地存储 -> 本地目标目录
2. 设置 -> 手动部署 -> 本地目标目录
3. 任务编辑 -> 本地路径覆盖（可选）

它们目前都主要依赖手输路径，存在两个问题：

1. Windows 桌面场景下，用户更常见的操作是“点图标选目录”，而不是复制粘贴完整路径。
2. 这 3 处路径输入的交互不一致，后续继续扩展时容易变成重复实现。

用户已明确选择采用“组件化方案”，因此这次不做零散补丁，而是统一抽成可复用的目录输入组件。

## 2. 目标与非目标

### 2.1 目标

1. 为上述 3 处路径输入统一增加“选择目录”能力。
2. 保留手动输入路径的能力，不强制只能通过选择器填写。
3. 让 3 处路径输入共享同一套 UI 结构、图标按钮样式和选择逻辑。
4. 把任务编辑中的“本地路径覆盖（可选）”改成更符合心智的“本地路径”。
5. 清楚表达任务级本地路径的默认行为：留空时使用设置中的全局本地目标目录。

### 2.2 非目标

1. 本次不修改 Tauri 后端目录选择命令，继续复用现有 `open_directory`。
2. 本次不改变任务配置的数据结构，`task.local_path` 仍保持可为空。
3. 本次不改动扫描、复制、部署等后端执行语义。
4. 本次不顺带重构整个设置页表单系统，只抽离目录输入这一类控件。

## 3. 决策结论

采用一个共享的“路径输入 + 选目录按钮”组件，供设置页 3 个入口复用。

推荐组件形态：

1. 组件名：`DirectoryPathInput.vue`
2. 建议位置：`src/components/settings/DirectoryPathInput.vue`
3. 组件职责：
   - 渲染文本输入框
   - 渲染右侧目录选择图标按钮
   - 点击按钮时调用现有目录选择能力
   - 用户取消选择时不报错、不清空原值
   - 保持与当前设置页一致的边框、圆角、focus、hover 语言

不把它做成过度通用的“所有路径都能选文件/目录”的万能组件，避免超出本次范围。

## 4. 组件设计

### 4.1 组件结构

组件视觉结构为一行：

1. 左侧主输入框：显示和编辑当前路径
2. 右侧图标按钮：使用 `FolderOpen` 图标，点击后打开目录选择器

交互规则：

1. 输入框支持直接键盘编辑。
2. 点击目录按钮后调用现有 `openDirectory()`。
3. 成功选择目录后，将结果回填到输入框。
4. 如果用户取消选择，保持当前值不变。
5. 如果打开目录选择器失败，沿用页面现有错误提示方式。

### 4.2 组件接口

组件最小接口建议：

1. `v-model`：当前路径字符串
2. `placeholder`：输入框占位文案
3. `title`：目录按钮悬浮提示，复用“打开目录”或“选择目录”类文案
4. `disabled`：需要时可禁用

为了兼容任务编辑里的可空值，组件内部应兼容空字符串展示；父级可决定是否把 `null` 映射为空字符串。

### 4.3 样式约束

1. 输入框和按钮组合后应维持单行对齐。
2. 按钮视觉与当前设置页路径区已有的 `FolderOpen` / `Copy` 小按钮保持一致。
3. 图标按钮需有明确 hover、focus-visible、cursor 样式。
4. 小屏下保持同一行优先；如宽度不足，按钮仍应紧贴输入框右侧，不拆成下一行。

## 5. 三个使用入口的行为

### 5.1 设置 -> 本地存储 -> 本地目标目录

绑定字段：`config.local_path`

行为：

1. 输入框继续允许手动修改。
2. 右侧新增目录选择图标按钮。
3. 选择目录后直接写入 `config.local_path`。
4. 底部说明文案维持“文件将被拷贝到此目录”。

### 5.2 设置 -> 手动部署 -> 本地目标目录

绑定字段：`manualLocalPath`

行为：

1. 输入框继续允许手动输入文件夹路径。
2. 右侧新增目录选择图标按钮。
3. 目录选择后直接写入 `manualLocalPath`。
4. 该区域只选择目录，不扩展到“选文件”模式；本次按用户要求聚焦目录选择能力。

## 5.3 任务编辑 -> 本地路径

原字段和语义：

1. 字段仍使用 `taskForm.local_path`
2. 底层仍为“可为空”的任务级本地路径
3. 为空时，实际回落到全局 `config.local_path`

UI 调整：

1. 标签从“本地路径覆盖（可选）”改为“本地路径”
2. 输入框改为复用目录选择组件
3. placeholder 默认显示全局本地目标目录，帮助用户理解默认值来源
4. 在输入框下补充一条说明文案：
   - 中文：留空时使用“本地存储”中的本地目标目录
   - 英文：Leave empty to use the Local Storage target directory

这样既保留原有行为，又避免“覆盖”一词带来的理解负担。

## 6. 文案调整

本次需同步更新中英文文案：

1. `localPathOverride` 改名为 `localPathTask` 或直接复用 `localPath`
2. 新增任务级说明文案 key，用于解释“留空即使用全局默认目录”
3. 如有需要，为目录按钮补充 tooltip 文案

原则：

1. 用户可感知的是“本地路径”，不是“覆盖机制”
2. 默认值来源要靠说明文案说清楚，而不是靠用户猜测

## 7. 实现影响面

预计涉及以下文件：

1. `src/components/settings/DirectoryPathInput.vue`
2. `src/pages/SettingsPage.vue`
3. `src/locales/messages.ts`
4. `src/lib/tauri.ts`

说明：

1. `src/lib/tauri.ts` 已存在 `openDirectory()` 封装，本次主要是复用，不预期改后端命令。
2. 若 `SettingsPage.vue` 中任务级字段需要把 `null` 与空字符串互转，可在页面内通过 `computed` 适配，避免把复杂语义塞进组件。

## 8. 验收标准

1. 设置 -> 本地存储 -> 本地目标目录右侧有目录选择图标，点击后可选择文件夹并回填。
2. 设置 -> 手动部署 -> 本地目标目录右侧有目录选择图标，点击后可选择文件夹并回填。
3. 任务编辑中的“本地路径覆盖（可选）”已改为“本地路径”。
4. 任务编辑中的本地路径也支持目录选择按钮。
5. 任务编辑留空时，界面上能明确理解为“使用全局本地目标目录”。
6. 用户取消目录选择不会清空已有值，也不会报错。
7. 中英文文案完整，3 处路径输入视觉风格一致。

## 9. 风险与约束

1. 手动部署当前底层字段名仍叫 `manualLocalPath`，但本次不改命名语义，只改交互方式。
2. 任务级字段是可空值，组件化时要避免出现 `null` 直接绑定输入框导致的显示问题。
3. 当前仓库存在其他未提交改动，实施时要最小化改动范围，避免误碰无关设置项。

## 10. 设计结论

这次不是给 3 个输入框分别补一个按钮，而是把“目录路径输入”正式提升为设置页里的复用模式：

1. 同一种任务使用同一种交互
2. 任务级路径不再用“覆盖”来表述，而是直接用“本地路径”表达
3. 默认回落全局目录的规则通过 UI 明确展示，而不是隐含在实现里

在不改变底层配置语义的前提下，这个方案能明显提升可发现性、一致性和后续可维护性。
