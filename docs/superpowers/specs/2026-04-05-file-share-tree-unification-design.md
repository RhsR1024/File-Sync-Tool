# 文件共享目录树统一建模设计

- 日期：2026-04-05
- 状态：已确认设计，待用户审阅后进入实现
- 实施分支：`main`
- 目标：把“共享根”和“普通目录”统一为单一目录树模型，首页直接展示可见共享项，移除共享根切换器

## 1. 背景

当前文件共享 Web 页仍以“`root + path`”为核心状态：

- 页面先选择共享根
- 再浏览该共享根下的目录
- 首页并不是一个真实目录层级，只是共享根选择器

这会带来几个问题：

- 用户会感知到“共享根”这个实现概念，而不是自然的目录层级
- 顶层共享项、普通目录、搜索结果不是同一种数据模型
- 顶层共享项的下载、重命名、删除都需要额外特殊判断
- 后续如果继续扩展搜索、收藏、最近访问、虚拟分组，会持续受两套模型影响

本次重构目标是把文件共享浏览体验改成真正的“树”：

- 首页直接显示当前账号可见的共享项，如 `soft / soft2 / soft3`
- 点击后进入对应内容，形成自然层级
- 搜索默认覆盖所有可见共享项及其内容
- 搜索结果既返回共享项自身，也返回其内部目录和文件
- 顶层共享项支持真实下载、重命名、删除，并同步更新共享配置

## 2. 设计目标

### 2.1 体验目标

1. 首次进入页面时，不出现“共享根”选择器。
2. 首页直接显示所有当前账号可见的共享项。
3. 首页共享项像普通目录一样可点击进入。
4. 首页默认搜索全部可见共享项及其内容。
5. 顶层共享项的目录下载按钮统一显示为紧凑的“下载”按钮。
6. 顶层隐藏 `上传文件 / 上传目录 / 新建文本 / 新建目录`。
7. 顶层仅在权限允许时显示共享项的 `下载 / 重命名 / 删除`。

### 2.2 架构目标

1. 后端提供统一目录树 API，而不是让前端手动拼 `root + path`。
2. 共享项、目录、文件使用统一节点模型。
3. 前端状态以“当前节点”驱动，而不是“当前共享根 + 当前路径”。
4. 顶层共享项的真实重命名和删除必须同步持久化配置。
5. 旧逻辑允许在迁移期短暂共存，但新前端必须只依赖新目录树模型。

## 3. 统一节点模型

后端新增统一节点响应模型，至少包含以下字段：

```ts
type FileShareNodeKind = 'share_root' | 'directory' | 'file';

interface FileShareNode {
  node_id: string;
  parent_id: string | null;
  kind: FileShareNodeKind;
  name: string;
  root_id: string;
  root_alias: string;
  relative_path: string;
  display_path: string;
  is_dir: boolean;
  size: number | null;
  modified: string | null;
  permissions: FileSharePermissionSet;
}
```

字段约束：

1. `node_id` 是前端可持有的稳定节点标识。
2. `share_root` 的 `relative_path` 固定为空字符串，表示共享项自身。
3. `directory` 和 `file` 的 `relative_path` 始终相对所属共享项根目录。
4. `display_path` 用于搜索结果展示完整定位路径，例如 `soft/实用工具/Drawio`。
5. `permissions` 按当前登录账号计算，不允许前端自行推断。

`node_id` 规则：

1. `share_root` 节点使用稳定的共享项 `root_id` 派生，重命名后不变。
2. 普通目录和文件节点使用 `root_id + normalized_relative_path` 派生，路径变化时重新生成。
3. 前端把 `node_id` 当作 opaque token 使用，不做字符串解析。

## 4. API 设计

### 4.1 目录树 API

新增：

```http
GET /api/tree
GET /api/tree?node_id=<id>
```

返回：

```ts
interface FileShareTreeResponse {
  current: {
    node_id: string | null;
    name: string;
    kind: 'home' | 'share_root' | 'directory';
  };
  breadcrumbs: Array<{
    node_id: string | null;
    label: string;
  }>;
  children: FileShareNode[];
}
```

约束：

1. 不带 `node_id` 时返回首页虚拟节点，`current.kind = 'home'`。
2. 首页 `children` 为当前账号可见的所有共享项，节点类型均为 `share_root`。
3. 带 `node_id` 时返回该节点的直接子节点。
4. `file` 节点不可作为目录树查询目标；若传入文件节点，返回 400。
5. 顶层面包屑固定以 `首页` 开始。

### 4.2 搜索 API

新增：

```http
GET /api/tree/search?keyword=<kw>
GET /api/tree/search?keyword=<kw>&node_id=<id>
```

返回：

```ts
interface FileShareSearchResponse {
  scope: 'global' | 'subtree';
  results: FileShareNode[];
}
```

约束：

1. 不带 `node_id` 时，搜索所有当前账号可见共享项及其内容。
2. 带 `node_id` 时，仅搜索该节点子树。
3. 搜索结果必须包含命中的 `share_root` 节点自身。
4. 搜索结果点击后可直接定位到命中节点。

### 4.3 节点操作 API

新增统一节点操作接口：

```http
POST   /api/nodes/directory
POST   /api/nodes/text
PATCH  /api/nodes/rename
DELETE /api/nodes
POST   /api/upload/files
POST   /api/upload/directory
GET    /api/download/file?node_id=<id>
GET    /api/download/archive?node_id=<id>
GET    /api/preview?node_id=<id>
```

请求约束：

1. 创建目录和文本接口以 `parent_node_id` 作为父节点定位参数。
2. 上传接口也使用 `parent_node_id`，不再让前端传 `root + parent path`。
3. 重命名和删除接口统一接收 `node_id`。
4. `download/file` 仅允许文件节点。
5. `download/archive` 允许 `share_root` 和 `directory`。
6. `preview` 仅允许可预览图片文件。

兼容策略：

1. 旧 `root + path` 相关接口先保留，直到新前端稳定。
2. 新前端只使用新目录树 API。
3. 清理旧接口时，必须先移除前端对共享根切换器的依赖。

## 5. 顶层共享项的真实操作语义

首页展示的 `share_root` 节点不是伪目录，而是真实可操作节点。

### 5.1 下载

1. 首页共享项显示紧凑“下载”按钮。
2. 点击后执行整个共享目录的 ZIP 下载。
3. UI 不再显示“打包下载”字样，只显示“下载”。

### 5.2 重命名

1. 首页对共享项点击重命名时，真正重命名磁盘目录。
2. 成功后同步更新共享配置中的 `root.path`。
3. `root.id` 保持不变，作为共享项稳定身份。
4. 如果磁盘目录重命名成功但配置保存失败，必须尝试回滚目录名，避免留下半成功状态。

### 5.3 删除

1. 首页对共享项点击删除时，真正删除该共享目录。
2. 删除动作继续遵循现有删除模式：回收站或永久删除。
3. 删除成功后，必须从共享配置中移除对应 `root`。
4. 删除后若用户当前正在该共享项内部浏览，前端应自动返回首页并刷新。

## 6. 权限模型

顶层共享项不使用特殊权限规则，直接复用统一权限字段：

1. `download_archive` 控制共享项下载按钮。
2. `rename` 控制共享项重命名按钮。
3. `delete` 控制共享项删除按钮。
4. `upload_file / upload_directory / create_directory / create_text` 在首页一律不显示。
5. 进入某个共享项或其子目录后，再按当前节点权限显示上传和新建按钮。

这样可以保持：

- 访客通常只看到进入和下载
- 被赋予写权限的账号才会看到共享项级重命名和删除

## 7. 前端重构方案

### 7.1 页面状态

前端状态从：

- `currentRoot`
- `currentPath`

重构为：

- `currentNodeId | null`
- `currentNodeMeta`
- `breadcrumbs`
- `children`

说明：

1. `null` 表示首页虚拟节点。
2. 页面只围绕“当前节点及其子节点”工作。
3. 搜索结果也复用统一节点模型，不再额外拼接根和路径。

### 7.2 页面结构

页面顶部工具区改为：

1. 左侧：面包屑，格式 `首页 / soft / 子目录`
2. 中间：搜索框
3. 右侧：账号状态、切换账号/退出、刷新、当前节点允许的写操作

首页时：

1. 不显示共享根切换器。
2. 不显示上传和新建按钮。
3. 列表直接展示 `share_root` 节点。

进入共享项或普通目录后：

1. 继续使用同一张表格。
2. 根据权限显示上传文件、上传目录、新建文本、新建目录。

### 7.3 列表渲染

列表统一渲染 `FileShareNode`：

1. `share_root` 和 `directory` 显示为目录样式。
2. `file` 显示为文件样式。
3. 操作列收敛为更紧凑的按钮样式，贴近 CHFS 的密度，不再占用过多宽度。
4. 目录类节点下载按钮统一显示为“下载”，具体下载行为由节点类型决定。

### 7.4 搜索行为

1. 首页默认搜索全部可见共享项及其内容。
2. 首页搜索结果要包含共享项自身。
3. 进入某个共享项或目录后，保留“当前目录搜索 / 全局搜索”两种模式。
4. 首页默认搜索模式为全局。
5. 进入目录后默认搜索模式为当前目录。

## 8. 后端实现方案

### 8.1 新增节点转换层

新增一层专用的节点转换逻辑，负责：

1. 把持久化 `root` 转成 `share_root` 节点。
2. 把 `ops::DirEntry` 转成统一 `directory/file` 节点。
3. 为搜索结果补齐统一节点字段和权限字段。

### 8.2 根级操作协调

新增专门的共享项级操作函数，而不是把空路径当作特殊值硬塞进普通目录逻辑。

建议新增：

1. `rename_share_root(...)`
2. `delete_share_root(...)`
3. `download_share_root(...)`

这些函数负责：

1. 文件系统操作
2. 配置同步更新
3. 错误回滚
4. 返回最新共享项状态

### 8.3 迁移策略

迁移顺序：

1. 先补统一节点模型和树 API
2. 再补搜索 API 和根级真实操作
3. 最后切前端到新 API
4. 新前端稳定后移除旧共享根切换逻辑

## 9. 测试计划

### 9.1 后端

新增或更新测试覆盖：

1. 首页树接口返回多个可见共享项节点。
2. 首页树接口按账号权限过滤共享项。
3. 首页搜索能命中共享项自身和其内部节点。
4. 目录树子节点接口返回统一节点结构。
5. 顶层共享项下载命中正确目录。
6. 顶层共享项重命名后磁盘路径与配置同步更新。
7. 顶层共享项删除后磁盘目录与配置同步移除。
8. 权限不足时，根级重命名和删除被拒绝。

### 9.2 前端

验证项：

1. 首页不再出现共享根切换器。
2. 首页直接显示多个共享项。
3. 首页隐藏上传和新建按钮。
4. 首页共享项显示紧凑下载按钮。
5. 搜索默认覆盖所有可见共享项及其内容。
6. 搜索结果能跳转到正确节点。
7. 访客和写权限用户的按钮显示差异正确。

## 10. 风险与约束

### 10.1 高风险点

1. 顶层共享项重命名会同时影响磁盘路径和持久化配置。
2. 顶层共享项删除会影响磁盘内容和共享配置。
3. 前端导航从 `root + path` 切到 `node_id` 后，面包屑和搜索跳转容易出现错位。

### 10.2 约束

1. 不允许仅通过前端假装目录层级，而后端仍保持共享根切换语义。
2. 不允许把共享项级真实重命名和删除塞进普通目录接口的“空路径特判”里。
3. 新前端必须只消费统一节点模型。

## 11. 实施结果定义

本设计完成后，用户应获得以下体验：

1. 打开文件共享页面后，直接看到 `soft / soft2 / soft3` 这样的顶层目录。
2. 无需理解“共享根”概念，也无需手动切换共享根。
3. 顶层共享项可以像真实目录一样进入、下载，并在权限允许时重命名和删除。
4. 搜索默认覆盖全部可见共享项及其内容，并能返回共享项本身。
5. 顶层和普通目录使用同一种节点模型，后续功能扩展不再依赖两套状态体系。
